# 并发与稳定性真实栈验证

这套工具在独立环境里运行实际 FastAPI、事务 Outbox、Celery Worker/Beat、PostgreSQL、Redis 限流器、图像裁切、结构验证、评分汇总和检查点逻辑。模型替身是单独监听 HTTP 的 OpenAI 兼容服务；生产代码没有 mock 开关，也没有替换 Pipeline 或 Calls。

所有模型响应均为合成数据。测出的吞吐量只描述本机、模拟延迟和此测试配置，不能推算真实模型的速度、评分质量或账单。

仓库包含压测代码和复现说明，`data/` 下的已有输入、日志、报告与数据库快照仅保留在本地。运行工具会重新生成合成数据与报告。

## 复现

需要已运行的本地 PostgreSQL `127.0.0.1:15432` 和 Redis `127.0.0.1:16379`，开发用户为 `ai4edu`，并允许创建测试数据库。工具不启动、停止或改动这些共用服务器。

```bash
.venv/bin/python -m pytest tests/test_loadtest.py
.venv/bin/python scripts/run_loadtest.py
```

可以指定唯一的运行标识；只接受小写字母、数字、下划线，长度上限 35：

```bash
.venv/bin/python scripts/run_loadtest.py --run-id 20261107_example
```

`--smoke` 把主场景缩减为 8 名考生，保留其他场景及真实 300 秒恢复等待。该结果不能当作千人验收。

## 隔离边界

| 资源 | 工具使用范围 |
|---|---|
| PostgreSQL | 新建 `ai4edu_loadtest_<run_id>`，保留以便复核 |
| Redis | 仅逻辑 DB 3；不执行 FLUSHDB/FLUSHALL |
| API | `127.0.0.1:18090` |
| 兼容模型 HTTP 服务 | `127.0.0.1:18091` |
| 资源与报告 | `data/loadtest/<run_id>/` |
| Celery | 独立进程、唯一 Worker 名称、独立 Beat 调度文件 |
| 凭据 | 子进程环境显式覆盖 API key/base URL/所有角色模型/价格/存储/预算限流设置；`credentials_file` 为空 |

工具不读取 `bailian.txt`，不打印环境变量，不向任何真实模型服务发请求。子进程在新建的运行目录下启动，避免读取项目根目录 `.env`，并去除继承的所有 AI4EDU/OPENAI/DASHSCOPE 配置后写入隔离配置。可同时保留正式栈的 API 18000、Redis DB 0 和正式数据库。工具拒绝复用已占用的 18090/18091 端口；Redis DB 3 如果已有待处理队列，也会拒绝消费。

正常完成或 Python 异常时都会停止本次启动的进程，删除本次新增的 Redis 键，保留数据库、图片和报告。不要在另一个进程里同时启动第二套 DB 3 测试。若操作系统强制终止整个 runner，应根据 `report.json` / `runner-events.jsonl` 中的 PID 清理该次进程，不能批量终止同机器的所有 Celery 进程。

## 验证内容

1. 并发 16 的小诊断：16 名考生，每人 5 题，共 80 个答案。生产 RedisLimiter 限制同一模型的所有角色请求。
2. 并发 32 的千人场景：1,000 个独立 candidate_id、5,000 个独立答案，完整 API 提交。每名考生上传一张独特的合成答卷，模型版面服务返回 5 个区域，实际代码裁切并保存。每个区域的像素包含不同考生和题号，裁切后仍保持独特。
3. 主场景必须观察到 1,000 次 PageLayout、5,000 次 Transcript、5,000 次 Judgment，另外 10 次 Rubric。只有数据库答案数量符合而实际 HTTP 工作量不足时，验收不通过。
4. 对成功批次重复提交相同幂等键，并通过实际 Outbox 重复发送候选准备和答案评分任务，核对同一 job_id、没有新增模型调用和分数副作用。
5. 用稳定种子和实际图像内容选择 429、503、超时、非法 JSON、非法证据。先保留终态失败记录，再仅调用 `/v1/jobs/{id}/retry`。已经成功的答案保持不变，失败答案的成功转写检查点复用，只重新请求失败的 Judgment。失败 ModelCall 审计保留。
6. 一个具有 `ExamInput.budget_cny` 的试卷下并发提交两个批次。让兼容服务不返回 usage，检查跨批次的原子预留、实际预算停止、未知用量保留预留，试卷 committed_cost 不超过总预算。价格为合成的 1 元/百万输入 Token 和 1 元/百万输出 Token。
7. 对另外 2 名考生的 10 个 running 答案实际 SIGKILL 自己的评分 Worker，然后启动新 Worker。SQL 任务租约和 Redis 准入票据均等待真实的 300 秒自然到期，Beat 执行恢复，没有手动更改 lease_until 或删除活跃票据。等待期间可继续运行隔离故障/预算场景。

评分 Worker 使用 Celery `threads` 池、48 个线程，预处理 Worker 为 16 线程。实际模型并发上限由共享 RedisLimiter 的 16/32 控制；测量峰值必须大于 1 且不超过配置。高并发线程数量本身不作为并发执行证据，证据来自独立 HTTP 服务的 inflight 计数。

## 报告与审计

每次运行生成：

- `report.json`：机器可读配置、状态、逐项验收、实际调用数、提交耗时、吞吐量、预算、重试、自然恢复、进程 PID/停止记录与数据库行数。
- `report.zh-CN.md`：中文结果和复现入口。
- `model-http-calls.jsonl`：每个真实 HTTP 到达请求的 schema、图像 ID、稳定身份、故障类型、状态码及模拟响应时长，不记录凭据。
- `*-submission.json`、`inputs/*.png`：可复核的实际 API 输入。
- `*-api-results.jsonl`：分页从实际 API 读出的候选和答案结果。
- `runner-events.jsonl`、各进程 `.log`：启动、停止、进度、SIGKILL 和恢复记录。

资源采样尝试读取本次进程的 RSS/CPU。在本地安全沙箱阻止 `ps` 时，报告记录不可用原因，不中止测试。当前采样是操作系统提供的近似值，不属于容量验收门槛。

进程崩溃时，对已经发送但没有结算的模型请求，服务无法知道真实用量，因此原来的 ModelCall 可能保留 `running` 和未知费用预留。重启后答案仍须收敛到唯一可查询的终态；报告单独记录这些旧调用的审计数量，不把它们当成成功结算。

## 契约测试

测试使用与生产相同的 JSON Schema 和评分验证函数，核对独立 HTTP 服务返回的评分细则满分、实际 image_id 证据关联和确定性错误；并测试请求重叠、故障种子与到达顺序无关、环境隔离、独特裁切结果、验收逻辑拒绝漏题/重复/缓存消除工作量/串行执行，以及操作系统阻止可选资源采样时的行为。
