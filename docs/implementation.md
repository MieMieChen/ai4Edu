# 主观题评分后端实施记录

日期：2026-11-07

目标：基于 FastAPI、Celery、Redis、PostgreSQL 和百炼接口，实现无教师审核的自动主观题评分服务。支持按题图片与整卷图片；模型按角色配置，模型选型由另一 session 完成。

工作分解与验证顺序：

- [x] 评分契约：评分细则总分、评分点覆盖、证据引用、无法判读状态；对应 `schemas.py`、`scoring.py` 及业务测试。
- [x] 图像与存储：旋转坐标、裁切、透明背景、分辨率预算、PDF 展页；48个图像测试与独立审查通过。
- [x] 数据与接口：上传、试卷、批次、进度、结果、失败重试；1000名考生请求拆分为5000条评分记录的用例通过。
- [x] 百炼调用：严格 JSON、usage、调用记录、费用预留、共享限流；两个候选模型的真实图像接口探测成功。
- [x] 自动流水线：评分细则生成/核验、定位、独立转写、判分、按风险及抽样复判；已修复并发提交、重复重试、过期执行覆盖及容量排队问题。
- [x] 交付材料与代码验证：Docker Compose、凭据文件读取、配置示例、样本导入命令、中文 README；92个测试、Ruff、编译与分发包构建通过。

后续已完成真实依赖容器与本机应用集成、完整1000人/5000题的独立模拟模型队列与故障测试，以及真实50题A/B/C对照。暂选Plus独立转写与主评，Max生成核验细则；输出上限分为8192/4096，跨图自然分片并发并保留检查点。真实模型峰值16并发；270项代码测试通过。验证条件、费用及尚未验证范围见 `verification.md`。

实现边界：不实现教师复核队列，不修改原始数据和已有模型评测文档。只在任务边界记录失败，不做模型替换、JSON修复或模拟评分。Redis 调度可重放，数据库状态与任务租约防止已完成任务重复执行；模型请求超时后的账单需以百炼实际账单为准。

当前目录没有 Git 仓库，因此在当前目录创建独立后端包，不操作 Git 分支。

## 初期存储范围与后期云端迁移

2026-11-07 用户确认：初期按当前存储能力推进基本功能验证。标准化整页图片、判分裁图保存在本地文件存储，结构化业务数据和图片引用保存在 PostgreSQL。上传原始 JPG/PNG/PDF 文件的独立归档保留为后期事项。

后期网站上线时，将本地数据迁移到云端，范围包括：

- 图片文件迁移至云端对象存储，沿用现有 OSS 存储适配接口。
- PostgreSQL 业务数据迁移至云端数据库，包括历史成绩、评分细则、转写、调用与费用记录及图片引用。
- 校验文件哈希、记录数量及图片引用对应关系，确保迁移后的结果仍可追溯。
- 在上线部署阶段安排 API、Worker、Redis 队列的云端配置与切换。

上述事项属于后期计划，不计入初期基本框架的完成条件；本次确认不启动云端迁移或新增原件归档实现。
